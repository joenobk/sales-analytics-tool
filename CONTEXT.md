## v6.04 — V7 Phase 2: entity/concept resolution (session 12)
New **Entities** module on SalesCore resolves dimension values to canonical entities, per PRD Phase 2. Concept binding maps every column to a concept (product/account/rep/territory/geography/campaign/opportunity/activity/time/amount) via role + synonyms + learned overrides; identifier columns default to product so ID-only files still report the entity as present. **ID + label pairing** (`pairIdLabel`) detects `*_id` ↔ `*_name` pairs by name pattern + cardinality — a few IDs with competing labels are still paired (that is what conflict review exists for), but broadly many-to-many mappings and geo/time/measure columns are excluded. The per-concept **entity registry** groups rows by ID, displays the label when one exists, and surfaces any ID with >1 label as an explicit **conflict** in a new "Entity review" card on the mapping panel — resolved only by user pick (persisted per header shape) or named rule (`most-frequent`/`most-recent`), never silently. **Fuzzy matching** normalizes names and scores bigram similarity: ≥0.92 auto-accepts, 0.75–0.92 goes to a human review queue in the same card ("Same entity" confirms; confirmed aliases persist across files via localStorage). Hierarchy suggestions (child values coinciding with single parents) are offered for confirmation only. **Data coverage** is first-class: a "Concept coverage" card shows present/partial/absent concepts per file, and `buildAiPrompt` now appends a DATA COVERAGE section naming absent concepts so the model says "cannot be computed" instead of speculating. IDs stay strings end-to-end (leading zeros survive load + join). Harnesses grew: `.verify-core.js` adds Phase 2 blocks (pair detection, leading-zero distinctness, conflict surfacing + both resolution rules, fuzzy queue/persisted alias, coverage ABSENT + schema payload) — all pass; real-Chrome e2e (`e2e-v7.js`, session-state dir) grows a dedicated `phase2_fixture.csv` section: pair detected, X-9 conflict surfaced and manually resolved (persisted), 5 rows load with "00123" ≠ "123", coverage correct for both files. New **Tools** module on SalesCore: `TOOL_DEFS` registry (list_datasets, describe_schema, query, compare_periods, create_chart, get_chart_data, extract_text_insights); `parseToolBlock` (the constrained protocol — a single fenced JSON block `{"tool": "...", "args": {...}}`; returns `{tool,args}`, `{error}` for a malformed-but-present block, or `null` when absent); `runTool(name, args, ctx)` executes deterministically against the app-provided dataset context (query groups by dimensions and returns a `resultId` + cap/truncation note; compare_periods returns current/prior/yearAgo/delta/deltaPct; create_chart validates via Phase 5 then renders; get_chart_data returns the exact series behind a rendered chart; extract_text_insights is the Phase 8 stub); `toolLoop({maxTurns, messages, context, callModel})` is the async loop — it terminates at `maxTurns`, and a malformed tool block produces a corrective message to the model rather than crashing; and `openProfile(rows, mapping, aggMode)` builds a deterministic opening profile (rowCount, dateRange, total, top/bottom, trend, season, coverage, top-5 share) that renders immediately without blocking on the model. Harnesses grew: `.verify-core.js` adds Phase 6 blocks 6.1–6.7 (valid/malformed/no tool-block parsing, loop executes a tool then answers, loop stops at the cap with hitCap, malformed mid-loop yields a corrective message, describe_schema, openProfile). ## v6.05 — V7 Phase 3: multi-dataset registry (session 13)
Phase 3 makes the tool multi-source, per PRD Phase 3. **Inline SheetJS (xlsx 0.20.3)** enables workbooks: the file input accepts CSV/XLSX with `multiple`, every sheet with a header row + data becomes a candidate dataset (raw:false keeps textual representations so leading zeros survive), and queued sheets confirm one at a time through the existing mapping panel. A **dataset registry** (`Datasets` module + app layer) tracks every loaded source: id, name, source file, load time, row count, schema, kind (transactions when time+measure exist, generic otherwise — a hint, never a hard requirement), mapping (concept-bound), entity registry, rows; only metadata persists to localStorage (`salesDatasets`), so reloads restore ↻ placeholder tabs that ask to re-load the source. Each file/sheet becomes its own tab plus an **Overview** tab with cross-dataset KPIs (dataset count, total rows, total filtered rows, declared joins). **Relationships**: concept-based joins are proposed automatically for dataset pairs (≥25% value overlap on shared concepts via `Joins.propose`), confirmed by the user, then evaluated (`Joins.evaluate` stats) and used for left-join enrichment lookups (`Joins.enrichColumn`, hash index built once at declaration) with a live "joined amount total" preview on the from-side dataset. **Global filter bus**: product/country filters and the date range apply per dataset through mapped concepts (`columnForConcept`); a filter never reaches a dataset lacking that column, and the Overview shows a visible "no 'X' column — this filter does not reach this dataset" note for each skipped case; the date range is universal for any dataset with a time column. Robustness fixes that fell out of multi-source testing: a lenient `parseGeneric` path loads files that lack the full transaction shape (all roles optional, no rows dropped, warnings instead of errors), time formats are now resolved from the actual data rather than trusting a persisted format from another source (`resolveTimeFormat`), and the view layer no longer crashes on null dates (aggregate/filteredRows guards). Harnesses grew: `.verify-core.js` adds a data-first format-resolution regression; real-Chrome e2e (`e2e-v7.js`) adds 15 Phase 3 checks — promotions fixture (no country column) loads leniently, three datasets coexist without collision, tabs preserve each dataset, product join proposed + declared with exact enrichment sum (13,734,800), overview notes "no 'country' column" for the skipped dataset, workbook sheets queue into the mapping panel, reload restores placeholders. All prior checks still pass; zero console errors.
