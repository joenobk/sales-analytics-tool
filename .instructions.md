# Project Rules — Sales Data Analytics Tool

## Mission
Build and maintain a single-file, no-build-step web app (`index.html`) that implements the phased V7 workbench in `PRD.md`, preserving `Historical_Data.csv` regression results.

## Loop-Trap Detection & Handling (MANDATORY)
A "loop trap" is repeating the same action without new information. Rules:
1. NEVER run the identical tool call twice in a row unless the first was truncated or errored mid-way. If it failed, change something (different args, different tool, smaller scope).
2. After any failed or empty result: STOP → read the output → pick ONE different approach. Never retry the same command 3+ times; after 2 failures on one path you MUST switch strategy and note why in DEVLOG.md.
3. Work in steps of at most 5 tool calls. At each step boundary, verify concrete progress (a file exists, a test passed, output changed). No verifiable progress = stop and re-plan, don't grind.
4. Decide once: when ambiguous, state the assumption and proceed. Do not re-deliberate decisions already recorded in CONTEXT.md or DEVLOG.md.
5. If you notice yourself about to repeat an action from earlier this session (same command, same edit), that is a loop signal: switch approach immediately and log it under "Loop traps hit" in DEVLOG.md.
6. Long-running commands get one wait + one re-check; if still running, do other work instead of polling again.

## General Rules
- YOU MUST keep all five core files current (PRD.md, .instructions.md, DEVLOG.md, CONTEXT.md, .env) and update them at session close.
- NEVER commit `.env` or any real API key to git.
- NEVER hard-code CSV data into the app; data comes from user upload only.
- The deliverable is ONE self-contained `index.html` (all dependencies inlined; no CDN). No build step, no npm.
- Keep this file under 100 lines. If it grows, cut fluff first.

## Definition of Done (per session)
- Work in CONTEXT.md completed and verified by actually running/inspecting the result.
- DEVLOG.md has an entry for this session; CONTEXT.md points at the next step.
- `git status` clean: all intended files committed and pushed.
